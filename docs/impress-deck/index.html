WhyCode

Why is this code like this?
Ask its own history.

Team FORTEC Ronit Shrimankar (lead) · Anshul Kamthe · Udita Singh

Built on django/django

01 · The problem

Decisions nobody
can explain any more

  • Codebases accumulate decisions whose reasons are forgotten.
  • New developers guess why a piece of code exists.
  • A wrong guess breaks things the original author fixed on purpose.
  • The reasons are scattered across commits, pull requests and tickets.
02 · The solution

Ask the history,
get a cited answer

Ingest
A public repo's history becomes a graph.
Ask
Plain-language why questions.
Evidence
Every answer carries its chain + a confidence score.
Refuse
No evidence? It refuses. Never invents.
03 · How it works

From history to answer

  1. 1
    Ingest — gh CLI for commits & PRs, plus Trac tickets and Django Enhancement Proposals. Django uses Trac, not GitHub Issues.
  2. 2
    Graph — entities: commit, PR, ticket, file, person, design doc. Edges: authored, fixes, references, touches, supersedes, mentions.
  3. 3
    Ask — evidence chain, supersession flags, refusal when evidence is absent.
  4. 4
    Runs anywhere — bundled SQLite database, no credentials, no paid APIs.

06 · The refusal

When it doesn't know,
it says so

$ python -m whycode.cli --question "Why does
  Django use a microservices architecture?"
refused: true   confidence: 0.0
No evidence in the graph answers this.
Refusing to invent an answer.

An earlier version answered this from an unrelated docs commit. The absent-term rule + a regression test fixed that for good.
